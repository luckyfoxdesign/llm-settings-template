Возьми задачу из `docs/backlog/todo/` в работу и начни её выполнять.

## Шаг 1 — выбери задачу

Если пользователь передал аргумент (название или номер задачи) — найди подходящий файл в `docs/backlog/todo/` по частичному совпадению имени файла или заголовка.

Если аргумента нет — прочитай список файлов в `docs/backlog/todo/`, покажи задачи в порядке числового приоритета (NN в имени файла, меньше = важнее) и спроси какую берём.

Дождись выбора, затем продолжай.

## Шаг 2 — переноси файл в wip/

Перемести выбранный файл из `docs/backlog/todo/` в `docs/wip/`. Имя файла сохраняется без изменений.

Подтверди перенос одной строкой: `Задача перенесена: docs/wip/<filename>`.

## Шаг 3 — инспекция контекста

Прочитай последовательно:

1. `PROJECT_MAP.md` — карта модулей, архитектура, таблица "Если нужно сделать X"
2. `CLAUDE.md` — архитектурные паттерны и правила проекта
3. Файл задачи из `docs/wip/<filename>` — цель, шаги, Definition of Done

После чтения выведи короткий план — 3–7 пунктов — что конкретно будешь делать и в каком порядке. Не начинай реализацию пока пользователь не подтвердит план (или не скажет "давай" / "поехали").

## Шаг 4 — выполняй задачу

Реализуй согласно плану. Придерживайся правил из `CLAUDE.md`:
- user_id-изоляция на уровне сервисов
- тесты только через Docker
- минимум комментариев, никаких лишних абстракций

По завершении подскажи пользователю: "Готово. Можно закрыть задачу командой `/complete-task`."
