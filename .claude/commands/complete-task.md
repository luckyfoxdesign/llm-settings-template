Выполни завершение задачи по правилам docs/folder-rules.md текущего проекта.

## Шаг 1 — определи задачу

Посмотри на текущий контекст разговора: какой файл из `docs/wip/` обсуждался или над чем шла работа. Если задача очевидна из контекста — используй её. Если нет — прочитай содержимое `docs/wip/` и спроси пользователя какую задачу завершаем.

## Шаг 2 — определи slug

Из имени файла извлеки `slug.md` — убери префикс с датой и приоритетом:
- `dd-mm-yy-NN-slug.md` → `slug.md` (задачи из todo)
- `dd-mm-yy-slug.md` → `slug.md` (баги)

Это имя файла в `docs/done/long/` и `docs/done/short/`.

## Шаг 3 — прочитай файл задачи

Прочитай содержимое файла из `docs/wip/` чтобы понять что было сделано.

## Шаг 4 — сделай коммит

Проверь `git status`. Если есть незакоммиченные изменения — сделай коммит:
1. Покажи пользователю какие файлы будут закоммичены.
2. Составь сообщение коммита в стиле `feat: ...` по изменениям.
3. Сделай `git add` нужных файлов и `git commit`. Не коммить `.env`, `docs/`, `.claude/`.
4. Запомни хэш коммита — он пойдёт в поле **Commit:** документов.

Если изменений нет — возьми хэш последнего коммита (`git log -1 --oneline`).

## Шаг 5 — создай docs/done/long/slug.md

Перемести содержимое файла из `docs/wip/` в `docs/done/long/slug.md`. Добавь в начало файла поле:

```
**Commit:** `abc1234` — "feat: описание"
```

Добавь в конец файла ссылку:

```
[Краткое резюме](../short/slug.md)
```

## Шаг 6 — создай docs/done/short/slug.md

Составь краткое резюме на основе прочитанного файла задачи. Формат:

```markdown
# Название задачи

**Commit:** `abc1234` — "feat: описание"

## Что сделано

- Пункт 1
- Пункт 2

---
[Полный план](../long/slug.md)
Closes #N  ← если задача закрывает GitHub issue, иначе удали эту строку
```

## Шаг 7 — удали файл из docs/wip/

Удали оригинальный файл из `docs/wip/`.

## Шаг 8 — подтверди

Выведи что было сделано: какие файлы созданы, какой удалён.
